A. Proteger mejor _isProcessing
Ahora usas un bool _isProcessing para impedir que arranquen varios procesadores a la vez. Eso funciona en muchos casos, pero no es totalmente seguro si entran lecturas muy seguidas desde distintos eventos. Hoy haces:
C#
if (_isProcessing) return;
_isProcessing = true;
Eso puede tener condición de carrera. �
GitHub
Para dejarlo más sólido, cambia eso por un lock simple.
Agrega este campo:
C#
private readonly object _queueLock = new object();
Y cambia StartProcessingQueue() por:
C#
private async Task StartProcessingQueue()
{
    lock (_queueLock)
    {
        if (_isProcessing) return;
        _isProcessing = true;
    }

    try
    {
        while (_queue.TryDequeue(out var request))
        {
            await Task.Run(() => ProcesarVinculacion(request));
        }
    }
    finally
    {
        lock (_queueLock)
        {
            _isProcessing = false;
        }

        if (!_queue.IsEmpty)
        {
            _ = StartProcessingQueue();
        }
    }
}
Eso evita que se queden elementos en cola si entró uno nuevo justo cuando salía el procesamiento.

5. Cómo dejarlo funcionando con el Enter del lector
En frmLector, tu CodBarras_KeyDown debería quedar así:
C#
private void CodBarras_KeyDown(object sender, KeyEventArgs e)
{
    if (e.KeyCode == Keys.Enter)
    {
        e.SuppressKeyPress = true;

        _ultimoCodigoBarra = (CodBarras.Text ?? "").Trim();

        if (string.IsNullOrWhiteSpace(_ultimoCodigoBarra))
        {
            toolStripStatusLbl.Text = "Código de barras vacío";
            return;
        }

        toolStripStatusLbl.Text = "Código de barras leído: " + _ultimoCodigoBarra;

        IntentarVincular();
    }
}
Y IntentarVincular() debe seguir siendo el punto donde se juntan:
_ultimoCodigoBarra
_ultimoRfid
Si ambos existen, encolas el request.
