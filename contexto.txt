Sí, eso pasa porque en Load estás aplicando muchos cambios visuales después de que el formulario ya empezó a mostrarse. Por eso se ve una “vista previa” fea y luego se reacomoda.
Qué te recomiendo
No hagas todo el rediseño pesado en Load si puedes evitarlo.
Mejor orden
Lo visual fijo hazlo en el diseñador.
Lo mínimo indispensable en el constructor, después de InitializeComponent().
Lo que depende de datos o runtime en Shown, no en Load.
Suspende el layout mientras aplicas estilos.
La causa más común en tu caso
Seguramente tienes varias de estas cosas en frmLector_Load:
cambiar tamaños de tabs
dibujar tabs
cambiar fuentes
cambiar colores de grids
llenar combos
registrar eventos
crear columnas
enfocar controles
Todo eso junto hace que WinForms pinte una vez “como viene” y luego otra vez con el estilo aplicado.
Solución práctica
1) Usa SuspendLayout() y ResumeLayout()
En constructor o al inicio del Load:
C#
public frmLector(string codTrabajador, string datoUsuario, string turno)
{
    InitializeComponent();

    this.SuspendLayout();
    tabMenu.SuspendLayout();

    mCodTrabajador = codTrabajador;
    mUsuTrabajador = datoUsuario;
    mTurnoTrabajador = turno;

    this.Text = $"Vincular - Usuario: {mUsuTrabajador} - Trabajador: {mCodTrabajador}";

    AplicarEstiloInicial();

    tabMenu.ResumeLayout();
    this.ResumeLayout(false);
    this.PerformLayout();
}
2) Crea un método solo para estilo inicial
C#
private void AplicarEstiloInicial()
{
    tabMenu.DrawMode = TabDrawMode.OwnerDrawFixed;
    tabMenu.SizeMode = TabSizeMode.Fixed;
    tabMenu.Multiline = false;
    AdjustTabWidth(tabMenu);

    EstiloContenedorTablaRFID();
    ConfigurarEstiloDataGridView(DataGridView1);
    BloquearColumnasDataGridView1();

    EstiloBoton(btnClear, pinturaRojoIndio, pinturaBlanca, pinturaRojoCarmesi);
    EstiloBoton(btnLimpiarRFID, pinturaGrisClaro, pinturaNegra, pinturaPlata);
    EstiloBoton(BtnBuscarHM, pinturaVerdeMarMedio, pinturaBlanca, pinturaVerdeOscuro);
    EstiloBoton(BtnLimpiarHM, pinturaGrisClaro, pinturaNegra, pinturaPlata);

    EstiloTextBox(CodBarras);
    EstiloTextBox(TextBoxHM);
    EstiloTextBox(TextBoxOP);

    EstiloComboBox(cmbScanners);
    EstiloLabelMensaje(MsnVincular);
    EstiloLabelContador(lblTotalCount);
}
3) En Load deja solo lógica funcional
C#
private void frmLector_Load(object sender, EventArgs e)
{
    ConfigurarGridRfid();
    ActualizarTotalCount();
    SetMensajeVincular("");

    _vinculador = new VinculadorService();
    _vinculador.OnInfo += Vinculador_OnInfo;
    _vinculador.OnError += Vinculador_OnError;
    _vinculador.OnInsertadoOk += Vinculador_OnInsertadoOk;

    InicializarScanner();
}
4) Usa Shown para cosas pesadas o visuales finales
Shown ocurre cuando el form ya terminó de cargarse. Sirve para:
Focus()
mensajes iniciales
cargar scanner
poblar combo
C#
private void frmLector_Shown(object sender, EventArgs e)
{
    CodBarras.Focus();
    SetEstado("Listo para conectar", Color.DarkOrange);
}
¿Preload?
En WinForms, “preload” como en web no suele ser la mejor salida.
Lo mejor es:
diseñar lo máximo en el diseñador
aplicar estilo antes de mostrar
evitar recalcular tamaños varias veces
evitar llenar datos pesados al inicio
Lo más importante: no redimensionar todo en Load
Sí, coincido contigo: mejor no redimensionar fuerte en Load.
Haz esto:
tamaños fijos en diseñador
solo AdjustTabWidth(tabMenu) si es realmente necesario
si el tamaño del formulario no cambia, ni siquiera recalcules tabs al cargar
También ayuda mucho activar doble buffer
Para evitar parpadeo:
C#
public frmLector()
{
    InitializeComponent();
    this.SetStyle(ControlStyles.OptimizedDoubleBuffer | ControlStyles.AllPaintingInWmPaint | ControlStyles.UserPaint, true);
    this.UpdateStyles();
}
Y para DataGridView y TabControl, si quieres, también se puede forzar con reflexión, pero primero probaría con eso.
Mi recomendación final
Haz el estilo así:
Diseñador: posiciones, tamaños, textos base
Constructor: colores, fuentes, bordes, tabs
Load: lógica y eventos
Shown: focus y acciones finales
Eso te quitará mucho esa sensación de “primero se ve feo y luego se acomoda”.
Si quieres, te ordeno tu frmLector.cs en 4 bloques: constructor, AplicarEstiloInicial, Load y Shown, ya listo para pegar.
